# Native Nacos TLS/L4 deployment example

`manifest.yaml` is a two-replica Kubernetes example for **in-cluster** official Go Nacos SDK clients. Each stable StatefulSet DNS name is a separate SDK server address. The sidecar terminates TLS and creates one loopback backend connection per TLS connection; it does not multiplex different clients onto one backend HTTP/2 connection. The Grayling process binds native plaintext ports only to loopback and requires native SDK-token authentication. Do not expose those backend ports, and do not use `hostNetwork`.

Build `./cmd/grayling-native-proxy` with `CGO_ENABLED=0`, then build its image with `Dockerfile.proxy` and pin the resulting image digest in the manifest. Pin the Grayling image digest as well. Create the `grayling` namespace and two Secrets: `grayling-native-secrets` with `pg-dsn`, `redis-addr`, `auth-secret`; `grayling-native-tls` as a TLS Secret with a CA-signed certificate whose SAN covers both stable Pod DNS names. The example has no plaintext ingress Service and does not contain live credentials.

The `grayling-native-clients` namespace and `native-access=allowed` Pod label define the only native SDK sources; `grayling-admin` is the separate API management namespace. Only trusted namespace administrators may assign those labels. This NetworkPolicy relies on a CNI that actually enforces NetworkPolicy. Kubernetes policies are additive: inspect all policies selecting these Pods before deployment. Node, hostNetwork, and loopback traffic need separate controls; this example supports only ordinary in-cluster Pods. Keep the native Services internal, restrict node access separately, and reject any other ingress path that can reach 8848/9848.

Apply the manifest after replacing namespace and image references. Verify from both an allowed and a denied Pod on a different node, with Grayling running: TLS and official SDK reads/subscriptions/pushes must work only for the allowed Pod; both native ports must be refused from the denied Pod; direct Pod-IP access to 18848/19848 must fail. Repeat for both StatefulSet DNS names, then verify credential revocation, reconnect and failover. Save policy YAML, Pod placement, proxy logs mapping each client to its backend connection, and the paired output of `scripts/check_nacos_native_topology.py`. See `docs/Nacos原生客户端.md` for the evidence commands and support limits. The isolated Kind fixture in `test/cluster/kind` exercises the same proxy executable and Cilium NetworkPolicy behavior; it is a local acceptance simulation, not evidence for a particular production cluster.
