# 实验绑定并发冲突验收（2026-10-13）

## 场景与结果

在临时本机 JSON 数据仓库创建 Reviewed 实验 `exp-11`，绑定准备检查全部通过。浏览器提交绑定前，另一个已认证的 publisher 以最新 Flag revision 和 draft hash 保存了一份变更草稿；随后原管理员的绑定请求收到 409。

| 核验点 | 结果 |
| --- | --- |
| 第二位管理员保存变更草稿 | HTTP 200；草稿 `updatedBy=bind-race-editor-2`、状态 `editing` |
| 原管理员绑定请求 | HTTP 409；页面重新读取准备检查并标出从通过变为失败的“Flag 草稿没有待处理变更”项 |
| 实验状态 | 仍为 `reviewed`，没有只排期却缺少绑定草稿的中间状态 |
| 原管理员下一步 | Bind 按钮禁用；“打开 Flag 与草稿”“重新检查”仍可用 |
| 手机首屏 | 生命周期与冲突原因位于预注册长表格之前，见[390px 截图](mobile.png)；[桌面截图](desktop.png) |

服务端将实验状态迁移与高风险绑定草稿的提交收敛为一次存储写入，并在同一锁内检查实验状态、Flag revision 和完整草稿指纹。`TestExperimentLifecycleRepublishesFlag` 额外验证指纹过期时返回冲突、保留另一位编辑者草稿且实验不迁移。Web DOM 契约验证 409 文案、版本对照、变化项和重新读取失败状态。

浏览器验收通过临时页面拦截器在真实绑定 POST 前插入第二位管理员的真实 PUT 请求，仅用于复现竞态；服务端使用未修改的实际管理 API。截图和结果来自本机验收数据，未代表外部部署。
