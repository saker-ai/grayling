# Grayling Web 控制台页面规格与交付清单

> 版本：2026-10-13。状态：实施规格，非已上线能力声明。产品原则、导航和阶段依赖见 [重设计实施方案](Web控制台重设计实施方案.md)；实验领域门槛见 [增长实验实施方案](增长实验实施方案.md)。本文件用于拆分页面任务、评审设计和记录验收。

## 1. 产品体验契约

**核心工作：**发布负责人在有限时间内判断风险并执行安全的下一步；实验分析员判断数据是否可信；审批人依据变更和影响作决定；运维人员定位失败并恢复服务。首屏优先回答“当前发生什么、是否需要我行动、依据是什么、下一步在哪”。产品模式为 Operate：可扫描、可追溯、可恢复。视觉可以有 Grayling 自身的识别度，但不能让装饰盖过风险与证据。

**边界：**Web 不计算统计结论、不伪造风险评级、不把数据缺失显示为零、不替服务端判断 RBAC 和审批资格。错误、权限不足和数据水位都属于核心产品状态。真实身份、令牌明文、曝光凭据和用户级事件不进入 URL、报告或前端持久化缓存。

| 设计成功指标 | 验收定义 | 测量材料 |
| --- | --- | --- |
| 风险识别 | 在实验工作台首屏，无须展开折叠区即可找到状态、阻断原因、报告生成时间和可执行动作 | 健康、零样本、SRM、护栏破线、水位未到各一条真实响应 |
| 发布正确性 | Flag 发布前能看见当前版本、草稿差异、受影响对象、审批与回滚目标；409 后保留草稿 | 两名管理员分别创建和审批的浏览器记录 |
| 实验接入 | 新建者能确认随机化单元、指标版本、曝光模式和真实触发点；创建只得到 Draft | 完整向导和一次 onRender 接入记录 |
| 故障恢复 | 请求失败后解释影响、保留可用区域，并给出重试或排障入口 | 401/403/409/429/5xx、断网与部分 API 失败 |
| 多端与无障碍 | 390、768、1024、1440px 下关键任务完成；键盘和屏幕阅读器完成创建、审批、暂停 | 自动检查加人工操作记录 |

目标是任务可完成和决策可信。项目没有可证明的现状耗时基线，暂不写“提效 50%”等结果承诺；上线后记录任务成功率、误操作、完成耗时和求助点，再比较改版前后。

## 2. 页面框架和导航行为

```text
全局栏：Grayling / 工作空间 / 环境 / 会话与连接 / 语言 / 主题 / 帮助
侧栏：总览与待处理 | 发布 | 受众 | 实验 | AI 治理 | 审批 | 运维
内容：面包屑 → 页面标题与状态 → 首屏决策区 → 证据或编辑区 → 审计/历史
手机：紧凑全局栏 → 当前任务 → 内容 → 安全操作区；侧栏变为可关闭导航
```

切换工作空间或环境时，先检测未保存表单，再取消旧作用域请求和轮询，最后导航到新作用域的列表或总览。直接打开对象深链须先恢复会话并重新鉴权；无权访问显示安全错误，不泄漏对象名称。页面刷新后恢复筛选和对象位置，但不恢复过期权限或上次令牌明文。浏览器后退须回到同一作用域内之前的页面，不重复提交变更。

**全局状态优先级：**权限/会话失效 > 不可执行的危险状态 > 数据不健康 > 业务空状态 > 成功提示。同一屏最多一个主动作。列表可搜索、筛选、排序、分页或游标浏览；筛选状态反映在 URL 中，但不能包含敏感数据。长表格在手机使用记录卡与详情页，不靠整页横向滚动完成操作。

## 3. 页面库存与逐页交付

表中“API”是需求映射；标为“配套”的端点尚须后端交付，前端不得模拟真实结果。每个页面都要覆盖首次加载、空、成功、陈旧、错误、无权及长文本状态，差异写在表中。

| 页面 | 首屏必须回答 | 信息顺序与主动作 | API / 权限 | 手机与特殊状态 |
| --- | --- | --- | --- | --- |
| 工作空间总览 | 现在有什么风险，需要谁处理？ | 风险带 → 我的待审批 → 异常实验/放量 → 近期发布；进入最紧急事项 | 现有实验、报告、审批和发布列表并行聚合；按各资源 read 能力裁剪 | 每项一张可读卡；一个模块失败仅该模块标“暂不可用”，不得清零其他统计 |

| Flag 列表 | 哪些 Flag 运行、有风险或待发布？ | 草稿状态筛选、环境作用域切换 → 运行中实验高风险草稿与待审批优先 → 新建 | Flag read/write；现有列表只提供 Flag/草稿状态，尚无报告风险聚合 | 已有手机记录卡（键、状态、revision、更新时间）；跨身份可见性和真实风险聚合待验收 |

| Segment 列表与详情 | 谁会被命中，哪些 Flag 依赖它？ | 已发布状态 → 条件树 → 依赖/预览 → diff/历史；编辑 | Segment read/write、依赖索引为后端配套 | 条件组可逐层展开；循环依赖或正则错误定位到字段 |

| 实验效果报告 | 结论可信到什么程度？ | 口径/版本 → 主指标及区间 → 护栏 → 固定/序贯/贝叶斯独立区域 → 导出 | report/export；`report.read` | 表格优先；长图可展开；bandit 用独立奖励/反馈语义 |
| 放量时间轴 | 下一步何时、凭什么发生？ | 当前 step → 最早判定时间 → 上次门禁 → 后续 step → 历史；暂停/恢复 | rollout/审计；操作按发布能力 | 危险动作固定在安全操作区；必须显示环境、比例与回退行为 |
| 审批收件箱与详情 | 我该审哪件，风险是什么？ | 待本人 → 对象/申请人 → diff → 策略/影响 → 批准或拒绝 | 审批 API；服务端阻止自批 | 详情全屏；过期或已由他人处理后刷新状态，不重复提交 |
| AI 资源列表与详情 | 哪一版资源可用，被哪里使用？ | 资源来源/状态 → 当前固定版本 → 解析结果 → 依赖 → 历史；登记/撤销 | AI 资源 API；内容读权限独立；依赖和健康状态为配套 | 无内容权限显示元数据，遮蔽敏感变量；外部 Nacos 未提供健康 API 时只显示配置来源 |
| 模型白名单与 OpenAI 入口 | 哪些模型可用，调用如何命中？ | 白名单/入口作用域 → 变更影响 → 接入示例；编辑或复制配置 | AI 模型与入口 API；`ai.*` 能力 | 共享 Key 的用户级实验限制放在配置旁，不能只藏在帮助文档 |
| 求值调试 | 为什么命中这个结果？ | 作用域与输入 → 结果 → 命中规则/manifest revision → 安全摘要；运行求值 | debug API；调试只读能力 | 显示“无曝光求值”；不把原始身份放入可分享链接 |
| 令牌 | 哪个令牌仍有效，能做什么？ | 作用域/权限/到期 → 最近使用 → 撤销；创建 | token API；管理员能力 | 新令牌明文只在创建响应展示一次；离开或刷新后不可恢复 |
| 配额 | 当前使用是否接近限制？ | 当前/上限 → 趋势或时间窗口 → 修改后影响；保存 | quota API；读写能力分开 | 429 说明影响和重试窗口；修改需理由 |
| 审计 | 谁在何时改变了什么？ | 时间/对象/操作者筛选 → 记录 → 关联 diff/报告版本 | audit API；只读 | 游标翻页；原始敏感字段永不展示 |

## 4. 关键流程与页面内文案

### 4.1 创建、评审与启动实验

1. 在列表选择“新建实验”。每步都显示已选择的工作空间与环境，不能误把环境留到最后。
2. 选 Flag 与随机化单元后，显示稳定分流风险提示；变体比例的总和即时反馈，服务端最终校验。
3. 从指标目录选择明确版本；展示主指标方向、单位、分母和归因窗。护栏卡片说明破线后放量会暂停。
4. 必选曝光模式：`onDecision` 的示例是服务端决策立即生效；`onRender` 的示例是页面组件真正显示后提交曝光。此处同时填接入负责人和触发点记录，不能把“已求值”误写成“已曝光”。
5. 复核页以自然语言描述不可变合同与运行门槛；创建结果是 Draft。后续“提交评审 → 审批 → 绑定检查 → 发布 Flag → 启动”各是单独状态，页面不暗中跳步。

错误文案格式为“发生什么；影响什么；下一步”。例如：**“Flag revision 已变化。本次绑定未提交。请查看新旧规则差异并重新运行准备检查。”** 对 403 说明所需权限，对 429 说明可再次尝试时间，不暴露内部栈或 token。

### 4.2 诊断与放量

诊断页从分配到真实曝光再到有效转化，分别给唯一单元数、比率、时间窗和排除原因。随机化分配 SRM 与曝光 SRM 必须独立命名，曝光偏斜的解释是“触达或采集链路异常的线索”，不能直接声称分流器错误。跨变体污染、标签不一致和原始事件缺失列为阻断。缺少预注册漏损阈值时标“需人工复核”，不能自动判为健康。

放量动作引用同一份报告版本。若报告在打开确认框后变更，操作前重新取版本并要求重新核对；服务端依旧执行最终门禁。暂停和回滚确认框必须写出实验、环境、现阶段比例、执行后求值行为、理由以及审计落点。成功后跳到更新后的时间轴；失败时保留理由输入。

### 4.3 故障、空态与只读

| 状态 | 页面表达 | 可行动作 |
| --- | --- | --- |
| 尚未配置 | 解释还缺哪个对象与第一步；不用零值统计填满页面 | 创建、阅读接入步骤 |
| 已配置但无事件 | 区分“尚无分配”和“有分配但未曝光” | 查看接入诊断和采集凭证 |
| 数据未成熟 | 显示数据水位、最早可判定时间和原因 | 手动刷新或继续观察 |
| 局部 API 失败 | 已成功区域保留，失败卡片写“截至…/重试” | 重试该区域 |
| 关键报告失败 | 显示已知状态与失败时间，禁止推进 | 重试报告、查看审计、紧急回滚 |
| 权限不足 | 保留允许的只读信息，不给虚假的可点击动作 | 查看所需权限或切换账户 |
| 会话失效 | 当前编辑内容可暂存于当前会话，不提交；重登后重新校验 | 登录 |

[GOV.UK Design System 的验证恢复模式](https://design-system.service.gov.uk/patterns/validation/)要求在错误字段旁说明如何修正，并提供表单级错误摘要。Grayling 按此模式处理向导、规则编辑和审批理由；业务不合资格用独立状态页解释，避免装作字段格式错误。

## 5. 设计系统交付件

| 资产 | 最小规格 | 验收点 |
| --- | --- | --- |
| 语义色与主题 | canvas、surface、overlay、文字三级、边框两级、交互、成功/警告/危险/信息；深浅主题和系统跟随 | 同一状态在两主题含义一致；文本符合 WCAG 2.2 AA；不只靠颜色 |
| 字体与密度 | 正文 14–16px、标题三级、数字/ID 等宽、间距 4/8px 阶梯；长报告限制行长 | 200% 缩放内容不丢失；报告数值有单位和分母 |
| 基础控件 | 按钮、输入、选择、切换、标签、提示、状态带、表格、记录卡、页签、弹窗/抽屉 | 键盘与触控可用；主要触控目标 44×44px；危险动作区分明显 |
| 数据组件 | 样本流程、双层 SRM、主指标比较、护栏、放量时间轴、结构化 diff | 图表有同数据表格；空/缺失/小样本不画成成功 |
| 状态模板 | loading、empty、ready、stale、error、forbidden、conflict | 各模板写出下一步；旧值标注时间，不在刷新时闪成 0 |
| 文案词典 | 状态、统计术语、错误、按钮的中英成对词条 | `web/i18n.js` 完整覆盖；“放量完成”与“统计胜出”区分 |

动态更新通过合适的 live region 宣告；弹窗打开后焦点进入，关闭后回到触发元素；sticky 操作栏不遮住焦点或输入法。遵循 [WCAG 2.2 快速参考](https://www.w3.org/WAI/WCAG22/quickref/)中的 AA 要求。上述 44px 是本产品交互目标；WCAG 2.2 AA 的 2.5.8 基线是 24px 且有例外，不能把两者混称同一个标准。

## 6. 工程拆分、依赖与完成门

| 阶段 | 可单独交付的页面包 | 后端前置 | 完成证据 |
| --- | --- | --- | --- |
| U0 已有基础继续收口 | 全局壳、作用域切换、深链、主题、局部故障总览 | 现有 scope/capabilities | 刷新与跨作用域深链、390/1440px、语言与主题回归 |
| U1 | Flag 列表/详情/发布复核、Segment 编辑、审批收件箱 | 现有草稿、diff、审批、回滚；缺少的只读依赖索引需配套 | 两管理员完整发布/回滚、409、未保存保护、只读角色 |
| U2a | 实验列表、向导、指标目录、准备检查 | 指标目录与实验字段已交付；检查 API 若无可由现有读接口组成 | 创建 Draft、审批、绑定、onDecision/onRender 区分 |
| U2b | 实验工作台、诊断、报告、放量时间轴 | 诊断 API、报告聚合与阻断门同步上线 | 分配/曝光 SRM、零样本、污染、护栏、水位、bandit 独立视图 |
| U3 | AI 资源/模型、求值调试、令牌、配额、审计 | 现有 API；依赖索引、版本 diff、外部 Nacos 健康状态如需展示须先提供真实 API | 敏感内容和权限分离、撤销恢复、审计分页、故障态 |
| U4 | 全站文案、移动卡片、键盘与屏幕阅读器、性能 | 前述页面稳定 | 覆盖矩阵逐项签收、截图和 HTTP 证据归档 |

每个页面包的实现任务按“数据模型与 API 映射 → 页面结构和 i18n → 权限与状态机 → 移动布局 → 自动契约检查 → 真实浏览器验收”拆分。不要先画出会诱导错误决策的漂亮假图。真实 API 尚未提供的依赖数据必须在页面上标“尚无数据来源”或隐藏对应模块，并保留工程待办。

### 页面完成定义

1. 页面在两种语言、两种主题和四个目标宽度下可以完成主任务；截图与测试数据来源记录在 `docs/acceptance/`。
2. 用管理员、审批人和只读者验证可见内容、允许动作与服务端拒绝一致；跨工作空间对象不泄露。
3. 401、403、409、429、5xx、断网、零数据、陈旧数据至少各有代表性页面验收；危险动作失败不会丢失输入。
4. 图表和数字来自同一报告版本，标有时间、水位、口径和单位；不把预览当正式可重算结论。
5. `web/i18n_contract.mjs`、`web/capability_contract.mjs`、`web/render_contract.mjs`、`web/rollout_contract.mjs` 与相关 Go Web 契约测试通过；真实浏览器记录补足自动测试覆盖不到的交互。

### 待确认的产品输入

这些项目影响后续 UI 文案或默认行为，实施前由产品负责人在对应阶段确认，不阻塞已有确定范围：新实验的默认负责人来源、哪些环境允许紧急停用、AI 资源依赖索引是否能提供可信反向关系、组织内部的对比度/品牌资产要求。没有答案时采用服务端当前权限与状态机、明确“未知”或隐藏该附加信息，不自行推断业务事实。
