## 版本与证据

- GoLab 根 `LICENSE`、Python `pyproject.toml`、TypeScript `package.json` / `package-lock.json` 均声明 Apache-2.0；这只适用于 GoLab 自有代码。
- `go.mod` 与 `go.sum` 固定 gonacos 伪版本 `v0.0.0-20260706000526-514208bd40a1`；对应 [上游 commit](https://github.com/godeps/gonacos/tree/514208bd40a131b5badb830bff2daf704ab97ee9)。该树无 LICENSE/COPYING；README 的 MIT 文本明确写有 `placeholder — confirm before publishing`。GitHub 仓库许可证元数据也为空。这些都不是授权证明。
- [`third_party/licenses.json`](../third_party/licenses.json) 记录 `go list -m all` 的完整选定模块图（含测试/工具依赖）、两个发布命令实际引用的模块、模块替换、TypeScript 锁文件版本和每个运行时许可/NOTICE 文件的 SHA-256。[`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) 是运行时第三方声明。源码以本地模块缓存内选定版本为依据；`go.sum` 提供模块内容完整性证据。许可类型是自动初筛，最终应由发布审核人复核原文。
- TypeScript 锁文件的包是开发工具，不随 Go 二进制发布。Python SDK 无运行时第三方依赖，测试工具 `pytest` 不在发布范围。若将来单独分发 SDK 或附带依赖，需按其实际打包内容再生成对应声明。

## 分发义务与机器门槛

运行时依赖目前初筛为 MIT、BSD-2-Clause、BSD-3-Clause、Apache-2.0 和未解决的 gonacos。源码分发应保留适用许可、版权和 NOTICE；二进制分发应随包交付相应许可文本和署名，并按 Apache-2.0 的 NOTICE / 变更声明要求处理。`make dist` 先运行 `make release-check`，再构建二进制，打包根 LICENSE、README、第三方清单、各模块许可/NOTICE 全文。当前 gate 因 gonacos 缺口失败，不生成发布包；发布检查不读取 README 占位。

CI 的 `License evidence` workflow 在 `go.mod`、`go.sum`、TypeScript 锁文件及清单变化时重新计算并比对版本、运行时范围、许可文件哈希和声明；变更需运行 `python3 scripts/license_audit.py update` 后人工审查 diff。`make license-check` 可在阻断状态通过并提示；`make release-check` 必须在所有运行时许可证据已解决后通过。取得上游书面说明但没有仓库 LICENSE 时，应将该公开说明的永久链接和对应 commit 范围作为可校验证据加入清单与 gate；不得仅修改 README 或手工改状态。

## 上游不能授权时

1. **替换 gonacos**：通过 `internal/configstore` 和 `internal/ai` 适配界面引入有明确授权的配置/AI 底座，迁移不可变 revision、manifest、SSE/轮询收敛、AI prompt 版本与摘要及双节点恢复。工程粗估为数周级改造并需重跑 `test/smoke`、`test/e2e`、`test/cluster`、`test/boot`；实际工作量需原型验证。迁移前现有分发仍阻断。
2. **隔离或商用授权**：进程隔离只能改变部署边界，不能凭空产生 gonacos 的使用、复制或分发许可；需要权利人出具覆盖 SaaS 运行及所需分发方式的书面合同，并由法律负责人审查。合同尚未取得，法律结论为**未获准**，不能将该路径视为已通过。
3. **停用依赖功能**：若不再包含 gonacos 代码，需证明构建、二进制和部署都不含该模块，并重写相应配置及 AI 功能/测试；单纯关闭运行时开关不足以解决已链接二进制的分发问题。
