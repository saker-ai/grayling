# 求值诊断与事件

Go 本地 SDK、Python/TypeScript 远程 SDK 的求值结果共享 `decisionId`、
`manifestRevision`、`flagVersion`、`rule`、`bucket`、`reason`、`errorCode`、
`experiment`（ID、epoch、variant、source）、`snapshotAgeMillis` 和
`exposureEventId` 字段。`manifestRevision` 是整个原子快照的版本；
`flagVersion` 是该 flag 自己的发布版本。未同步过时 revision 为 0。
`snapshotAgeMillis` 从快照的 `generatedAt` 计算；Go SDK 的过期判定则以
最近一次成功同步为准。失败结果不代表变体分配。
Python/TypeScript 的类型化方法遇到与请求类型不符的远端值时，返回调用方
默认值，并统一设置 `failed=true`、`reason=ERROR` 和
`errorCode=TYPE_MISMATCH`；服务端决策诊断保留原始求值结果。

## 查一次决策

- Go：保留 `Result.DecisionID`，在同一个 `sdk.Client` 上调用
  `Diagnose(decisionID)`。OpenFeature 的 ID 位于 FlagMetadata 的
  `graylingDecisionId`。查询结果含求值依据、曝光状态和已排队的转化数。
- Python/TypeScript：保留 `details.result.decision_id` / `decisionId`，
  调用 `client.diagnose(id)`。底层 `GET /api/v1/sdk/decisions/{id}` 只接受
  SDK 凭证，并用凭证中的工作空间和环境检查归属。不存在及跨作用域均返回
  404。collect、admin 凭证不能代替 SDK 凭证。
- 两种查询都只保留最近 10000 个决策；服务进程重启、跨副本转发或超出
  保留窗口后可能查不到。调用者应在事故调查时保存采样事件或诊断响应。
  查询结果不含原始随机化单元和上下文属性，也不含其他租户规则。

`rule` 为命中规则名，未命名的规则用 `targeting[index]`，默认规则和实验
门禁默认回退用 `default`。`bucket=-1` 表示没有分桶。曝光状态为 `none`、
`queued`（本地已排队）、`submitted`（本地已发送，仍可能被服务端拒绝）、
`dropped`（本地未能发送）或 `recorded`（远端已入库）；转化计数在本地为
已排队数，在远端为当前进程已接收数。曝光/转化采集仍按原有服务端去重及
实验归因规则执行。
远端单次决策的诊断计数上限为 1024，超过时返回 `conversionsTruncated`；
该上限不影响实际采集或分析。

## 状态与事件

三个 SDK 均报告 `NOT_READY`、`READY`、`ERROR`、`STALE`；默认最大新鲜度
为五分钟，可按客户端配置。Go Provider 报告 OpenFeature 的
`PROVIDER_READY`、`PROVIDER_ERROR`、`PROVIDER_STALE` 和
`PROVIDER_CONFIGURATION_CHANGED`。首次快照由 READY 表示；后续 manifest
revision 变化（包括空环境 revision 0 首次发布）发配置变化事件。
重复失败及同 revision 重验不会重复发事件。Provider 的错误消息为固定
类别，不包含上游响应正文、凭证或单元 ID。恢复同步会重新发 READY。
Python/TypeScript 可通过 `status()` 的 `state`、`revision` 和 `lastError`
观察同一状态及版本；过期缓存不会继续返回为新鲜决策。

Go OpenFeature `client.Track` 使用 tracking event 名作为转化 metric key，
并从 tracking details 的 `decisionId` 找到先前的本地曝光；数值来自
`TrackingEventDetails.Value()`。例如：

```go
id := details.FlagMetadata["graylingDecisionId"].(string)
client.Track(ctx, "conversion", evalCtx,
    openfeature.NewTrackingEventDetails(1).Add("decisionId", id))
```

Python/TypeScript 继续用 `track_conversion` / `trackConversion(details, ...)`。
三种形态的转化采集都会携带 `decisionId`，与曝光事件和求值诊断关联。
没有先前曝光的 Track 调用不产生转化。

## 指标与可采样事件

`GET /api/v1/sdk/metrics` 返回当前凭证作用域的 `exposures` 和
`conversions` 两个已接受事件计数，不以用户、flag、实验或决策 ID 作维度。
Go 本地 `Status()` 同时提供求值、同步失败、曝光队列、采样丢弃等计数。
设置服务端 `-evaluation-sample-rate`（0 到 1，默认 0）可将采样的
`feature_flag.evaluation` 事件写成结构化日志。嵌入式 Server 的
`api.Options.EvaluationSampleRate` 和 Go SDK 的
`sdk.Options.EvaluationSampleRate` 分别控制远端和本地事件；消费
`SampledEvents()`。队列有界，满时丢弃采样而不阻塞求值。分析用曝光与
转化事件始终保持完整采集，不受该采样率影响。

采样事件使用 `feature_flag.key`、`feature_flag.provider.name`、
`feature_flag.result.reason`、`feature_flag.result.variant`、
`feature_flag.version`、`error.type` 等字段，并补充
`grayling.manifest.revision`、`grayling.snapshot.age_ms` 和 `decision_id`。
不输出原始单元 ID、上下文属性和任意 flag 值。采样事件的 ID 是高基数
关联字段，只用于日志，不用于指标维度。

OpenFeature [Events](https://openfeature.dev/specification/sections/events/) 与
[Tracking](https://openfeature.dev/specification/sections/tracking/) 定义了
Provider 状态事件和跟踪调用；Go SDK 的 Tracker 是可选接口。
OpenTelemetry [feature flag 语义约定](https://opentelemetry.io/docs/specs/semconv/feature-flags/)
仍处于 **Development**，其中 evaluation event 约定处于
[Release Candidate](https://opentelemetry.io/docs/specs/semconv/feature-flags/feature-flags-events/)。
因此日志字段采用明确的版本边界，后续升级规范时需复核映射。
