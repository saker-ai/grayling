# 漏斗与留存指标（Issue #10）

在创建固定比例实验时预注册 `primaryMetric.type` 为 `funnel` 或 `retention`。两者使用已采集的 `exposure`、`conversion` 事件；步骤和回访事件由转化的 `metricKey` 命名。事件 `unit` 经工作区 HMAC 转为 `unitHash`，采集时 `sessionId` 也经带域分隔符的 HMAC 处理。报告仅输出计数与原因，不输出单元或会话 ID。原始事件使用 PostgreSQL 持久化，可按注册版本和原始事件重新计算；本地增量后端只供预览，数据健康门禁止其自动决策。

```json
{
  "primaryMetric": {
    "key": "checkout", "type": "funnel", "direction": "increase",
    "funnel": {"steps": ["product_view", "add_to_cart", "purchase"], "dedupUnit": "user", "stepTimeout": 3600000000000}
  }
}
```

`steps` 至少两个、非空且互异；`stepTimeout` 是每两个相邻步骤之间的最大时间（纳秒，右端开区间）。`dedupUnit` 为 `user` 或 `session`。一个单元/会话的第一次首步进入分母；后续步骤必须严格晚于上一已匹配步骤、早于超时及 AnalysisWindow 结束。重复事件或重复步骤不会多计数；会话口径必须提供 `sessionId`。只有在实验窗口内完成的 split 曝光后的事件参与计算。会话口径跨会话分别计数，分配仍按随机化单元进行。

```json
{
  "primaryMetric": {
    "key": "d1_visit", "type": "retention", "direction": "increase",
    "retention": {"cohortKey": "signup", "returnKey": "visit", "day": 1, "timezone": "Asia/Shanghai"}
  }
}
```

`cohortKey` 为空时，cohort 起点是窗口内首次 split 曝光；否则是该单元曝光后、AnalysisWindow 结束前的首次同名转化。`day` 支持 1 或 7，`timezone` 必须是有效 IANA 时区。D1/D7 指 cohort 当地日期之后第 1/7 个自然日 `[当地零点, 次日零点)`，跨时区和夏令时按日历计算。回访转化允许发生在 AnalysisWindow 结束之后，但必须落在相应回访日内。没有 cohort 起点的随机化单元被排除；观察水位未到回访日终点的 cohort 标为 `immature`，既不算分母，也不算失败。该状态使报告不健康，自动放量保持等待。

`guardrails` 可用同样的 `type`、`funnel`/`retention` 定义和 `metricKey` 预注册旅程护栏；需设置正数 `minSample` 和非负 `maxRelativeRegression`。报告的 `journeys` 列出各臂的 `denominator`、`numerator`、`immature`、`excluded`（原因计数）、窗口定义及 72 小时迟到水位。窗口或原始事件校验失败、未成熟 cohort、护栏样本不足或基线为零时，数据健康门阻止自动决策。主指标沿用双比例检验；护栏只看预注册的相对退化幅度。报告每次从原始事件按 `clientTime,eventId` 排序重建，因而到达顺序不改变结果。
