# Grayling Web 控制台重设计实施方案

> 状态：分阶段实施中，2026-10-13。本方案覆盖 `web/` 中的整个管理控制台，保留现有管理能力和安全约束；未标明完成的页面规格仍待实施。增长实验服务端契约见 [增长实验实施方案](增长实验实施方案.md)。

逐页的信息层级、状态、接口、交互和验收任务见 [Web 控制台页面规格与交付清单](Web控制台页面规格与交付清单.md)。本文件说明产品方向和阶段依赖；页面规格是 U1–U4 的实现与评审清单。两份文档与代码不一致时，以实际 API 契约和测试结果为准，先更新文档再宣称页面完成。

当前已完成分组导航与手机菜单、跟随系统的明暗主题、工作空间/环境/对象 hash 深链、基于现有 API 的局部容错总览、双语指标目录的创建/审批/发布/弃用入口、实验主指标版本选择、曝光模式选择与说明、报告中的版本来源、分配/触达诊断摘要及独立诊断页、拒收原因细分，以及仅在页面可见时运行且失败退避的报告刷新。总览的完整风险摘要、实验向导、结构化编辑、响应式记录卡以及完整可访问性验收仍按本方案推进。

## 1. 产品判断与设计目标

Grayling 是灰度发布与实验决策台。核心用户是发布负责人、实验分析员、审批人和运维负责人；他们经常带着具体任务进入：确认今天能否推进、定位为何 HOLD、创建并评审实验、发布或回滚 Flag、核对 AI 资源状态。当前界面已经提供这些操作，但 [Web 管理覆盖矩阵](web-management-coverage.md)显示入口以资源类别平铺；[真实浏览器验收](acceptance/web-2026-10-08/report.md)发现实验绑定前置条件不易理解。现有 [实验详情截图](acceptance/web-2026-10-08/22-experiment-report.png)也显示预注册、生命周期、报告与放量同屏堆叠，零样本时技术字段占据主要视野。

重设计的主要成果不是换皮，而是让用户在十秒内看懂“现状、风险、下一步”，并能在每个危险动作前看见依据和影响。界面必须准确反映服务端数据：无真实曝光时显示“暂无可判定数据”，不能用占位数字或暗示胜出；不可重算的后端报告显示“预览”；不同统计方法的结果保持各自解释。管理台的主模式为 **Operate**：高频任务和扫描效率优先。

### 成功指标与验收样本

| 用户任务 | 设计后的成功条件 | 验收方式 |
| --- | --- | --- |
| 判断实验是否可推进 | 首屏可见结论、阻断原因、水位、护栏与当前放量阶段；能进入证据详情 | 用无样本、健康、SRM、护栏破线四组真实 API 数据走查 |
| 创建并启动实验 | 向导提示 Flag、随机化单元、指标、曝光模式、审批和绑定前置条件 | 两个管理员跨身份完成创建 → 评审 → 绑定 → Flag 审批发布 → 运行 |
| 发布或回滚 Flag | 清楚展示草稿与已发布差异、作用域、受影响实验、审批人和回滚目标 | 真实浏览器执行发布、409 冲突、紧急停用、回滚 |
| 审批变更 | 审批人能在一个屏幕看见风险摘要、结构化差异、申请人和不可自批原因 | 跨身份审批及只读角色验证 |
| 手机值守 | 不用横向滚动即可看状态、查看阻断原因、暂停和回滚；复杂编辑可以进入全屏表单 | 390px 触控和键盘检查 |

## 2. 导航与信息架构

全局栏固定显示品牌 `Grayling / GoLab`、工作空间、环境、连接/会话状态、语言与账户入口。切换工作空间或环境必须清空对象详情、停止轮询并提示未保存变更。当前作用域始终可见，不能仅凭 URL 猜测。旧页面 URL 不含具体对象路径；新方案采用可分享的客户端路径或 hash route，并在刷新后恢复当前范围与页面；跨作用域深链必须重新授权。

| 一级区域 | 二级页面 | 用户问题与主动作 | 当前来源 |
| --- | --- | --- | --- |
| 总览 | 工作空间概览、待处理 | “有什么需要我处理？”看异常实验、待审批、即将到门槛的放量、最近发布 | 新聚合视图；复用现有列表/报告/审批 API，必要时新增只读汇总 API |
| 发布 | Flag 列表、Flag 详情、草稿编辑、发布历史 | “哪个版本在服务？”创建、比较、审批、发布、回滚、紧急停用 | 当前 Flags；现有 Flag API |
| 受众 | Segment 列表、详情、预览 | “谁会被命中？”编辑条件、预览、审批、发布 | 当前 Segments；现有 Segment API |
| 实验 | 实验列表、创建向导、实验工作台、指标目录 | “分流是否可信，效果如何？”创建、评审、绑定、诊断、报告、放量 | 当前 Experiments；指标目录和诊断 API 为新增 |
| AI 治理 | 资源目录、资源详情、模型白名单 | “哪版 Prompt/资源被调用？”注册、固定版本、撤销/恢复、解析 | 当前 AI Resources；现有 AI API |
| 运维 | 求值调试、令牌、配额、审计 | “为什么命中、是否超限、谁改了什么？”安全操作与排障 | 当前 Debug、Tokens、Quotas、Audit |
| 审批 | 收件箱、详情、历史 | “这个变更该不该批？”先看影响再批准或拒绝 | 现有审批 API；当前入口应从相关页面的隐性流程提升为显性导航 |

桌面导航按上述区域分组，突出“待处理”数量和当前对象位置；不为每个子页面增加永久一级按钮。手机使用紧凑顶栏与可展开导航，当前任务的主要动作放在页面底部安全操作区；危急“暂停/紧急停用”应易找到，但不得误触。面包屑只显示作用域内层级，如 `实验 / exp-4 / 报告`。搜索先支持当前列表；跨资源全局搜索属于后续阶段，首版不伪造。

建议的客户端路径为 `/console/:workspace/:environment/overview`、`/flags/:key`、`/segments/:key`、`/experiments/:id/{summary,diagnostics,results,rollout,settings}`、`/metrics/:key/:version`、`/ai/resources/:type/:logical`、`/approvals/:id`、`/ops/{debug,tokens,quotas,audit}`。列表使用对应复数根路径。URL 仅表示导航状态；页面初始化仍以会话和 capabilities 重新确认工作空间/环境及对象权限。登录后无工作空间时转到创建引导，而不是空白总览。

## 3. 统一页面框架和视觉系统

视觉方向：面向值守和分析的克制控制台。把风险状态做成显眼而可读的状态带，数据表与证据区域保持高密度；大面积装饰不抢占工作空间。品牌保留现有中性深色基调和蓝色交互色，但重做层级、字号、间距与对比度；同时提供浅色主题，让长时间阅读报告更舒适。用户主题选择持久化，默认跟随系统；高风险状态不能只靠颜色表达。

设计 token 先在 `web/style.css` 或独立 token 文件定义语义变量：`surface.canvas/raised/overlay`、`text.primary/secondary/disabled`、`border.subtle/strong`、`action.primary`、`status.success/warning/danger/info`、焦点环、阴影、圆角和 4/8 像素间距阶梯。正文至少 14px，表格辅助文字至少 12px，主要数值 24–32px；最长的报告行限制阅读宽度。数字与 ID 使用等宽字体，普通说明使用系统 UI 字体。颜色指标满足 WCAG 2.2 AA 的文本对比；图表用形状、标签和线型双重编码。44×44px 是本产品的触控目标，比 [WCAG 2.2 AA 的 24×24px 最小目标及例外](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)更严格；可见焦点按 [WCAG 焦点可见要求](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible)验收。

组件层统一为：页面标题与状态栏、面包屑、摘要数字、状态带、时间轴、可筛选表格、抽屉/全屏表单、结构化 diff、证据面板、空状态、权限说明、错误恢复、危险动作确认框。每个状态都有 `loading / empty / ready / stale / error / forbidden` 模板；异步数据更新时保留旧结果并标记“截至何时”，而非闪烁为 0。toast 只报完成与非阻塞反馈；可恢复错误和阻断原因留在页面内。所有危险动作的确认框须包含对象、环境、影响、回退目标和操作者理由。

### 交互规则

- 一页一个主动作，其余放入有名称的次级操作区；危险动作和“保存草稿”不并排使用相似颜色。
- 表单在字段旁即时校验，并提供服务端返回错误的定位；429 显示重试信息，409 提示重新载入和对比，403 说明权限要求，401 回登录。不会用成功 toast 覆盖一次失败。
- 草稿离开保护扩展到实验向导、指标定义和 AI 注册；可恢复的临时输入只保存在当前浏览器会话，绝不含 token 明文。刷新后的恢复不能把旧草稿当已发布事实。
- 轮询默认只用于处于运行状态且页面可见的报告/放量；标签页隐藏时停止，回前台再取。显示更新时间、可手动刷新；错误后指数退避，不每 10 秒无限请求。
- “查看原始 JSON”放在证据折叠区，供专家排障；默认表单采用结构化字段和示例，不能把 JSON textarea 作为主要交互。
- 支持键盘焦点顺序、跳过导航、弹窗焦点陷阱和关闭后焦点恢复；状态变化通过合适的 live region 宣告。可见焦点不能被禁用态或 sticky 底栏遮挡。

## 4. 关键任务与页面规格

### 4.1 总览与待处理

总览顶部是一句可行动的工作区状态：“2 个实验暂停，1 项审批待处理”，下方按紧急程度展示：护栏破线/发布失败、等待审批、报告等待水位、今日计划步骤。每项显示对象、环境、最后变化时间、阻断原因和直达动作。统计卡片只显示真实可计算的数量，无法读取某模块时显示“该数据暂不可用”，其他模块继续呈现。只读者看到状态与详情，操作按钮由能力 API 决定。聚合 API 若暂未实现，可并行取现有端点并在前端合并，必须有请求数上限与取消机制。

### 4.2 Flag 与 Segment

Flag 列表默认按“运行中有风险/待审批/最近更新”排序；提供环境、状态、关联实验筛选。详情页左侧“当前发布版本”，右侧“草稿差异”，顶部给出影响范围、审批状态和发布依赖。编辑区分基本字段、规则、百分比分流、JSON 高级模式；高级模式修改后重新运行同一结构化校验。发布前复核页展示 revision、diff、受众估计、关联实验、回滚版本和审计理由。紧急停用展示停用后求值回退行为，不与常规发布共用确认语。

Segment 条件编辑器使用可读的字段/操作符/值行和嵌套组，右侧显示命中预览与依赖 Flag。保存前验证“至少一条条件或嵌套分群”、字段类型、正则和循环依赖；无权限时仍可查看已发布规则。保留 JSON 高级编辑与导入，但只有解析和语义校验都通过才允许保存。发布过的 Segment 显示被哪些 Flag 引用，编辑时告知影响范围。

### 4.3 实验创建向导

从“目标与假设 → 受众与分流 → 指标与护栏 → 曝光与接入 → 运行与复核”五步完成。每步有摘要与错误数，可前后返回；最后只创建 Draft，不暗中启动。首版默认呈现固定分流两变体。Bandit 放在明确标记的高级路径，隐藏固定样本胜出字段；多臂 Holm 也在高级路径，并解释确认性比较族。

1. 目标：实验名称、假设、关联 Flag、环境。Flag 不存在或不是可编辑状态时给出创建/返回路径。
2. 受众：随机化单元、资格比例、变体与占比、层互斥；占比总和实时显示。匿名登录及共享 Key 的身份风险要在此处提示。
3. 指标：从已发布目录选具体版本，明确主指标、方向、分母、转化窗口；护栏逐项显示触发后果。旧式内嵌指标仅在迁移/专家模式可见，不能与目录定义混淆。
4. 曝光：必须选 `onDecision` 或 `onRender` 并看对应集成示例；界面用“实际展示才计曝光”的具体示例解释区别。若选 `onRender`，要求填写展示触发点和集成负责人。
5. 复核：用人能读懂的文字总结不可变契约、运行窗口、最小样本、保留期、Flag 发布依赖和审批角色；展示机器校验项，通过后创建 Draft。服务端仍重复校验。

绑定前新增“准备检查”：Flag 已发布、百分比规则与实验占比/单元一致、当前 revision、所需审批、环境和模型资源状态。检查项若不通过，显示“去 Flag 草稿 / 去审批 / 重新检查”；不得让用户先点击 Bind 再从 400 猜原因。若状态在检查与提交间变化，409 页面展示最新状态并保留原操作上下文。

### 4.4 实验工作台

详情首页只回答四件事：当前状态、可否推进、原因、下一步。顶部状态带依次显示实验状态、epoch、Flag revision、注册版本、报告时间与环境。主体采用四个可直达的区域：**决策摘要**、**数据健康**、**效果证据**、**放量时间轴**；完整预注册契约置于“设置与审计”页签。页面不因没有事件而展示数页空统计字段。

| 状态 | 首屏主文案 | 主动作 |
| --- | --- | --- |
| Draft / Reviewed | “还未开始采集实验结果” + 绑定/审批前置步骤 | 查看准备检查、提交评审 |
| Running，无样本 | “等待首批实际曝光”；区分已分配但未触达和完全无分配 | 查看 SDK 接入和采集诊断 |
| Running，水位未到 | “结果未成熟，当前仅供观察”；显示预计可判定时间 | 查看水位、继续观察 |
| SRM / 污染 / 护栏异常 | “自动推进已阻止” + 具体原因、受影响范围、最近变化 | 查看诊断、暂停/回滚流程 |
| Healthy，可推进 | “数据满足当前放量门槛”；显示主指标及护栏证据，不宣称绝对获胜 | 查看证据、按权限推进 |
| Paused / Stopped / Archived | 操作原因、操作者、时间和回退位置 | 查看审计、允许的恢复动作 |

报告详情先显示样本流程 `分配 → 实际曝光 → 有效转化`，每步给出人数、漏损、时间窗和排除原因。主指标显示 A/B 原始值、绝对差、相对差、置信区间、方法和是否达到预注册 MDE；分母/单位始终可见。护栏显示“正常/破线/未成熟”，SRM 展示观测与预期分配及告警解释。序贯与贝叶斯各置独立“辅助分析”面板，文案明确它们不驱动当前自动门；Bandit 页面改为奖励/反馈延迟/冻结状态，不复用固定分流胜出 UI。漏斗和留存以步骤/队列图表展示，同时提供表格和 CSV 导出；数据不足时保留原因，不画虚假曲线。

放量页使用时间轴呈现各 step 的资格比例、最短停留、观察窗口、当前阶段、最早可判定时间、上次门禁结果。暂停、恢复、人工推进、接管和回滚均展示影响预览及理由字段，且按服务端状态机启用。自动完成最后 step 后显示“放量计划完成”，不等同于“确认性实验胜出”。报告和放量动作都能跳转到审计记录。

### 4.5 审批、AI 资源与运维

审批收件箱按等待本人、已处理、全部分组；每项显示变更对象、申请人、环境、风险、过期时间和可否由本人批准。详情以结构化 diff 为中心，固定展示审批策略、风险摘要和执行后果。审批与执行是两个不同动作；自批拒绝由服务端决定，前端提前解释。失败后保留详情与理由，不跳回列表。

AI 资源页分 Prompt/资源版本与模型白名单。资源详情显示逻辑名、当前固定版本、来源 Nacos 模式、可用/撤销状态、受影响 Flag/入口和最后解析结果。撤销/恢复的确认框说明下游解析将如何变化。内容访问权限与管理权限分开；无 `ai.content.read` 时只显示元数据。OpenAI 兼容入口的提示明确：仅修改 `baseURL` 可接入，但多人共享 Key 且不传可信 `user` 时不能形成用户级实验。

AI 场景采用专门任务流：先登记 Prompt/资源，再验证解析结果与模型白名单，再将资源版本绑定到 Flag/实验，最后观察效果和可回退版本。资源详情同时呈现“内容版本”和“当前调用入口”，让产品负责人知道改变资源会影响哪些实验。解析预览只展示当前 actor 有权读取的内容，默认遮蔽敏感变量；若现有 API 没有依赖关系或版本 diff，页面明确显示“尚无依赖数据”，对应的只读依赖索引和差异 API 列为 U3 的后端配套，不用前端猜测。对于外部 Nacos，展示连接模式、上次同步/读取状态和原生 AI 资源能力是否可用；这些状态必须来自真实健康接口，接口未提供前只显示配置来源，不伪造连通性。

调试页明确标为“无曝光求值”，展示输入上下文、命中规则、变体、manifest revision 和可复制的安全诊断摘要，不自动写实验事件。令牌页一次性明文仅在创建完成时显示；复制动作有时间限制、关闭后不可再看。配额页按“当前值/限制/修改后影响”呈现，保存前要求明确确认。审计页支持服务器端筛选、游标翻页、对象深链和时间范围；审计记录不可在 UI 编辑。

## 5. 权限、异常和数据可信度

所有页面先读现有 capabilities，再决定可见动作；管理端点继续在服务端逐次鉴权。权限不足的页面可读部分保留，隐藏或禁用敏感动作并说明所需角色。跨工作空间的深链返回安全的 403 页面，不能通过错误信息泄露对象是否存在。会话仍使用同源 HttpOnly Cookie 或仅内存保存的跨源 token，不能回退到 localStorage 存 token。

对报告数据定义统一来源标签：`真实可重算`、`本地/增量预览`、`数据未成熟`、`不可用`。UI 通过服务端 `window.backend/recomputable/complete` 与健康问题决定标签，不根据后端名称猜测。若部分 API 失败，总览展示局部故障；实验工作台的关键报告失败则禁止推进操作。所有图表提供同数据表格，导出包含生成时间、scope、epoch、指标版本和数据健康标记。

## 6. 响应式、语言与可访问性

目标断点以内容容纳能力而非设备名称定义：宽桌面 1440px 双列、普通桌面 1024px 主内容单列+侧栏、平板 768px 收起侧栏、手机 390px 全屏任务流。宽表格在手机切换为“每行一张记录卡”或有限列+详情抽屉；不能让页面整体横向滚动。表单按钮触控目标至少 44×44px；底部固定动作区不得遮住输入法和内容。图表高度受控，滚动时保留标题、范围和时间水位。

中文为默认语言，英文完整覆盖所有页面、状态、错误、日期与单位；专有名词首次出现附简短解释。时间显示本地时区并可查看 UTC 原值；留存 cohort 的业务时区单独标注。动态文本统一走 `web/i18n.js`，不得把新中文直接写进 JS 模板。错误消息应说明“发生什么、影响什么、下一步是什么”，不要只显示错误码。WCAG 2.2 AA 作为验收目标：语义标题、表单标签、表格标题、键盘全路径、焦点管理、对比度、缩放至 200%、减少动态效果偏好。

## 7. 前端技术实施

现有页面是 `web/index.html` + `web/app.js` + `web/style.css` + `web/i18n.js` 的原生 Web 应用，可分阶段演进，无需为了重设计立即换框架。先拆出路由/作用域状态、API 客户端、能力门控、国际化、基础组件与各资源页面模块；保留同源部署与安全模型。每个页面只管理自己的订阅/定时器，路由离开时取消 fetch 和轮询。新路由采用显式状态模型，URL 参数只含工作空间、环境和对象 ID，不含管理 token 或原始用户 ID。

| 阶段 | UI 工程交付 | 依赖与门槛 |
| --- | --- | --- |
| U0 基础框架 | token、主题、全局栏、分组导航、深链、错误/空状态组件；保留所有旧功能 | 现有 i18n、能力和渲染契约全通过；桌面/手机无导航回归 |
| U1 发布和审批 | Flag/Segment 结构化编辑、发布 diff、审批收件箱、危险动作确认 | 真实审批双人流程、409 冲突、未保存编辑与回滚实测 |
| U2 实验工作台 | 列表、向导、准备检查、报告摘要、放量时间轴 | 现有实验 API 可先改信息层级；新指标目录/诊断 UI 待对应 API 完成再开放 |
| U3 AI 与运维 | AI 资源、调试、令牌、配额、审计重排 | 权限分离、敏感信息显示规则、审计分页与 AI 撤销恢复实测 |
| U4 统一验收 | 全站中英、键盘、屏幕阅读器、移动、性能、异常态 | [覆盖矩阵](web-management-coverage.md)逐项更新，保存新浏览器证据和剩余限制 |

U0–U3 每次上线都维持所有现有管理动作可达。未完成的新后端能力显示为不可用状态或不显示，不提供“可点击但必然 404”的入口。旧深链若已存在则提供重定向；页面刷新后重建 scope 与 capability，不能凭本地缓存授权。对 `web/app.js` 的大模板字符串拆分按模块推进，每一阶段只迁移相关页面，避免一次性重写造成审计与权限回归。

## 8. 交付与验收清单

每个页面交付：桌面/手机布局、中文/英文文案、默认/加载/空/成功/错误/权限不足/过期状态、表单校验、键盘路径、API 映射、权限表和危险动作确认文案。设计稿应使用标记为“合成示例”的实验数据；上线截图和验收结论只使用真实服务端响应。设计评审需要同时看 390px 与 1440px，尤其是零样本报告、SRM、审批冲突和人工接管。

自动检查沿用 `web/i18n_contract.mjs`、`web/capability_contract.mjs`、`web/render_contract.mjs`、`web/rollout_contract.mjs` 和 Go 的 Web 渲染契约测试；新组件增加语义/权限契约，不为纯样式变化增加镜像测试。最终真实浏览器验收覆盖 [管理操作矩阵](web-management-coverage.md)列出的所有操作的可达性或仅 API 理由，关键闭环使用两个管理员与只读角色，记录 HTTP、页面状态、截图和未通过项。性能以首次可操作、列表千条与长报告交互为测量对象，避免为了视觉效果引入高成本动画。

## 9. 与工程方案的接口边界

Web 使用 [增长实验实施方案](增长实验实施方案.md)定义的指标目录、显式曝光和诊断 API；UI 不自行计算统计结论，不替服务端执行分桶、审批或放量门。前端可以计算比例和格式化时间用于输入反馈，但服务端始终重新验证。Web 产品重设计可先完成信息架构和旧功能迁移，指标目录、曝光模式、诊断的入口需随对应后端工作包上线。任何新增字段在 UI、OpenAPI、SDK 文档和服务端读模型中统一命名。
