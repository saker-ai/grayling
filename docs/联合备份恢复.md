# GoLab 联合备份与恢复演练

## 恢复单位和目标

一个恢复点必须同时包含：PostgreSQL **整个 GoLab 数据库**（schema、控制面、token 哈希、HMAC 密钥环、原始事件、去重账本、聚合及 AI 索引）、gonacos **完整 Snapshot**（Config、Auth、AI 等注册的 snapshotter）、gonacos `auth-secret`、恢复点 `point.json`。密钥环在 PG dump 中，不能单独生成或替换；`auth-secret` 关系到 gonacos token 和 Snapshot HMAC。实验报告从恢复后的原始事件重算。

目标：每 **15 分钟**完成并异地确认一组备份，故灾难 RPO ≤15 分钟；停写后开始的计划恢复 RPO=0。以隔离环境从取得密钥及介质到验证并开放 API 计，RTO ≤60 分钟。生产值需按实际数据库体量每月至少演练一次并记录；超限即扩容/调整流程，不能把小样本耗时当生产保证。每组归档在不可变、异地存储保留 35 天；另保留每月最后一组 12 个月。删除到期归档前核对最近两组已成功恢复，至少两名有权限人员可独立取回解密密钥。

备份必须先停止所有 GoLab 副本、proxy 写入口、事件采集、rollout、reconciler 和 gonacos 独立写入口，并等待在途请求完成。记录最后成功接收的事件时间和最后 manifest revision，此刻为逻辑恢复点。不要用运行中的 PostgreSQL dump 配合另一个时间的 Snapshot。若 15 分钟停写无法接受，应先实现跨组件一致性屏障；当前脚本是停写备份。

## 内嵌 gonacos 的可执行流程

准备与当前 PostgreSQL 主版本兼容的 `pg_dump`/`pg_restore`（缺失时脚本使用 Docker `postgres:16-alpine`；非 PG16 请安装对应版本客户端）、`gpg`、`jq`、`tar`、`sha256sum`、签名私钥、归档接收公钥及其离线托管的解密私钥。签名公钥指纹通过独立信任渠道预先登记。`auth-secret` 放在 0600 文件，使用仓库同一 commit 构建的 `golab`。归档目录必须为仅备份角色可写的异地不可变存储；传输和存储均加密，密钥托管与归档权限分离。不要把密钥文件、明文 dump 或进程参数放进工单。

```bash
export GOLAB_BIN=/opt/golab/bin/golab
export GOLAB_PG_DSN='postgres://.../golab?sslmode=verify-full'
export GOLAB_GONACOS_DATA=/var/lib/golab/gonacos
export GOLAB_AUTH_SECRET_FILE=/run/secrets/gonacos-auth
export GOLAB_GPG_RECIPIENT='backup-escrow@example.org'
export GOLAB_GPG_SIGNER='backup-signer@example.org'
export GOLAB_BACKUP_OUT=/secure/immutable/golab-$(date -u +%Y%m%dT%H%M%SZ).tar.gpg
./scripts/recovery-backup.sh
```

脚本在已停写的 PG 与 gonacos 状态上记录 schema 迁移、control version、每个环境 manifest/flag/segment revision、所有 PG 表内容摘要、事件账本数量、token 数量及密钥摘要；启动一个无对外监听的 gonacos 实例并在关闭时强制落盘 Snapshot，把完整 Snapshot 文件的 SHA-256 写入恢复点（包括 Auth/AI 状态），然后取 PG 自定义格式 dump。归档内各文件有 SHA-256 清单，整包由签名密钥签名并加密。备份成功后把 `point.json` 摘要、归档 URI、对象版本、备份开始/完成时间、最后写入时间、PG 与 gonacos Snapshot 大小写入演练记录。脚本只在全套成功时产生最终归档；失败时不要更新“最新可恢复点”。

在**全新、隔离**的目标 PG 数据库和空目录恢复；先验证归档签名指纹、文件哈希，再恢复 PG，比较 `database_states` 中的 schemaVersion 与归档恢复点，最后恢复 gonacos Snapshot 和密钥，运行只校验门禁。目标 PG 账户应无权访问生产库，检查 DSN 主机/库名两人复核。

```bash
export GOLAB_BACKUP_IN=/secure/immutable/golab-YYYYMMDDTHHMMSSZ.tar.gpg
export GOLAB_RESTORE_DIR=/var/lib/golab-restore/new-point
export GOLAB_GPG_SIGNER_FINGERPRINT='预登记的完整十六进制指纹'
export GOLAB_PG_DSN='postgres://.../empty_restore_db?sslmode=verify-full'
./scripts/recovery-restore.sh
```

`recovery-restore.sh` 拒绝非空目标库或已存在的目标目录。通过后用恢复目录的 `auth-secret`、`gonacos`、`point.json` 启动一次 `golab -pg ... -gonacos-data ... -auth-secret-file ... -recovery-point ...`；门禁在监听和后台写任务启动前执行。以后正常重启可不带一次性恢复点参数，必须保留相同的密钥与 Snapshot 严格加载配置（`GONACOS_STRICT_SNAPSHOT=1`）。对外放量前人工核对 SDK config/eval、管理 token、重复事件返回 `duplicates=1`、实验报告以及 `point.json` 中的 revision。恢复后只允许向前迁移：若新二进制迁移失败或报告不一致，停止服务，丢弃**隔离目标**并从原归档重新恢复、使用备份时二进制；不得在已迁移库上手工倒改 schema。

## 外部 Redis / 多副本

脚本针对 gonacos 内嵌 Snapshot 文件；外部 Redis 模式由 Redis 中的 gonacos Snapshot envelope 保存状态，`-gonacos-data` 不生效。先停止所有写入和副本；在停写屏障内执行 `golab -pg "$GOLAB_PG_DSN" -redis "$REDIS_ADDR" -auth-secret-file "$GOLAB_AUTH_SECRET_FILE" -gonacos-addr 127.0.0.1:0 -gonacos-grpc-addr 127.0.0.1:0 -write-recovery-point point.json`，等待退出（它会在关闭时保存 gonacos envelope），然后 `redis-cli -h <host> -p <port> SAVE` 并备份生成的完整 RDB，接着 `pg_dump -Fc -f postgres.dump "$GOLAB_PG_DSN"`。核对 RDB 中 `gonacos:snapshot` 存在，把 RDB、PG dump、`auth-secret`、checkpoint 和 SHA-256 清单放进**同一**签名加密归档，归档方式同内嵌脚本。具体 Redis HA/云服务应使用其受支持的一致性快照接口并记录快照 ID；不能只复制某个配置 key。恢复时在隔离 Redis 实例载入同一 RDB/AOF，空 PG 库执行 `pg_restore --exit-on-error --no-owner --no-acl`，先比对归档与目标 schemaVersion，随后用 `-redis <isolated-addr> -verify-recovery-point point.json` 校验；所有副本必须使用同一 PG、Redis 和 `auth-secret`。本脚本不自动操作外部 Redis 的持久化和拓扑切换。

隔离演练使用独立 Redis 实例与空 PG 数据库。停写后先记 `t_quiesce` 和最后成功事件时间；执行上述 checkpoint 后，在 Redis 上执行 `SAVE`（或经批准的云快照 API），等待快照完成并记录快照 ID/完成时刻；只有随后才做 PG dump。Redis RDB 必须包含 `gonacos:snapshot`，恢复到**不同实例**后先检查该 key，再启动只读 `-verify-recovery-point` 进程。错误密钥、旧 RDB、改过的 PG 数据分别应使门禁非零退出；每次失败均丢弃隔离目标，从同一归档重建，禁止在目标上修补 key。记录 `t_verify` 和 `t_open`，RTO=`t_open-t_restore_start`；计划停写若确认屏障后无成功写入且恢复点包含屏障前全部写入，则 RPO=0；灾难 RPO=`事故时间-最后可恢复归档的最后写入时间`。须同时核对两个租户的 SDK config/eval 不串读、事件 ID 重放 `duplicates=1`、历史实验报告及密钥环摘要；仅恢复点哈希相同不足以覆盖这些行为。

本仓库提供 [`scripts/recovery-external-drill.sh`](../scripts/recovery-external-drill.sh) 供**可销毁 Docker 测试容器**重放 PG dump + Redis 全量同步 RDB + checkpoint 校验及错误密钥/PG 篡改/缺 Snapshot 注入。它要求一个源 Redis、同一个 PG 测试容器中的两个独立数据库；目标库必须事先为空，脚本创建并销毁新的目标 Redis 容器。必须显式设置 `GOLAB_DRILL_DISPOSABLE_TARGET=YES`，并提供 `GOLAB_BIN`、`GOLAB_AUTH_SECRET_FILE`、`GOLAB_DRILL_SOURCE_PG_DSN`、`GOLAB_DRILL_TARGET_PG_DSN`、`GOLAB_DRILL_PG_CONTAINER`、`GOLAB_DRILL_PG_USER`、`GOLAB_DRILL_SOURCE_DB`、`GOLAB_DRILL_TARGET_DB`、`GOLAB_DRILL_SOURCE_REDIS_ADDR`、`GOLAB_DRILL_TARGET_REDIS_ADDR`、`GOLAB_DRILL_TARGET_REDIS_CONTAINER`。可另设 `GOLAB_DRILL_SDK_A_TOKEN_FILE`、`GOLAB_DRILL_SDK_B_TOKEN_FILE`、`GOLAB_DRILL_HTTP_ADDR`、`GOLAB_DRILL_HTTP_ADDR_B` 和两个租户的 `GOLAB_DRILL_A_VALUE`/`GOLAB_DRILL_B_VALUE`，核对隔离恢复后的双副本 config/eval；再提供 `GOLAB_DRILL_COLLECT_TOKEN_FILE`、`GOLAB_DRILL_DUPLICATE_EVENT_FILE`、`GOLAB_DRILL_OWNER_TOKEN_FILE`、`GOLAB_DRILL_EXP_ID_FILE`、`GOLAB_DRILL_REPORT_BEFORE_FILE` 即可核对去重和历史报告。脚本只适用于无 Redis 鉴权的隔离测试镜像，不能代替生产 Redis HA/云服务快照接口。脚本最后故意删除目标 Snapshot，随后销毁目标 Redis 容器；目标 PG 数据库也仅可作为测试残留，绝不可直接放量。

## 受控 HMAC 密钥轮换

轮换是**停写迁移**，不可在普通控制台或管理 API 执行。两名不同的全局 owner 分别持有自己的管理 token，由独立审批记录指定窗口、备份归档 ID、恢复点 SHA-256、回退负责人。先按上节完成联合备份并在隔离环境验证；轮换时所有 GoLab 副本、采集、发布、rollout 与 gonacos 独立写入必须停下。轮换密钥由受控随机源生成 32 字节，以 64 个十六进制字符放入 0600 临时文件；两个 token 分别放在 0600 文件，`auth-secret` 仍用 0600 文件。文件路径不能指向符号链接。不要在参数、工单、日志或控制台粘贴任何原始密钥或 token。

既有部署若只有初始全局 owner，在停写且验证一次联合备份后，用下列离线入口签发第二枚 owner token 至**尚不存在**的 0600 文件；`hmac.approver_provision` 审计与 token 同一 PG 事务。将文件交由独立审批人保管。**签发会改变 PG 恢复点**，必须重新完成联合备份并验证，轮换命令使用新的 `point.json`；不得沿用签发前的 checkpoint。审批人完成后撤销这枚 owner token 或将其纳入独立 escrow。操作人不得同时保管两枚凭证。

```bash
"$GOLAB_BIN" -pg "$GOLAB_PG_DSN" -redis "$REDIS_ADDR" \
  -gonacos-addr 127.0.0.1:0 -gonacos-grpc-addr 127.0.0.1:0 \
  -auth-secret-file "$GOLAB_AUTH_SECRET_FILE" \
  -rotation-backup-point /secure/backup/point-before-provision.json \
  -rotation-operator-token-file /run/secrets/golab-rotation-operator \
  -provision-rotation-approver-file /run/secrets/golab-rotation-approver
```

```bash
GOLAB_BIN=/opt/golab/bin/golab
GOLAB_PG_DSN='postgres://.../golab?sslmode=verify-full'
REDIS_ADDR=127.0.0.1:6379
GOLAB_AUTH_SECRET_FILE=/run/secrets/gonacos-auth
# 以下三个文件由不同保管人预置为 0600；密钥文件内容为 64 位十六进制。
"$GOLAB_BIN" -pg "$GOLAB_PG_DSN" -redis "$REDIS_ADDR" \
  -gonacos-addr 127.0.0.1:0 -gonacos-grpc-addr 127.0.0.1:0 \
  -auth-secret-file "$GOLAB_AUTH_SECRET_FILE" \
  -rotation-backup-point /secure/backup/point.json \
  -rotate-hmac-key-file /run/secrets/golab-next-hmac \
  -rotation-operator-token-file /run/secrets/golab-rotation-operator \
  -rotation-approver-token-file /run/secrets/golab-rotation-approver
```

命令先核对 PG、gonacos/Redis 与 `auth-secret` 与备份恢复点完全一致，然后验证两枚未撤销的全局 owner token 且 ID 不同。PG 中伪名迁移、密钥环新增及 `hmac.rotate` 审计在一个事务提交；审计仅含两个 token ID 和恢复点 SHA-256，绝不含原始密钥。命令不打开 HTTP/gRPC 监听器。执行人记录退出码、审计 ID、迁移前后密钥环版本数与哈希、耗时、后验 SDK/报告/去重/租户隔离结果。失败退出时保持停写，核对 PG 事务回滚与审计未提交；若状态不确定或后验核对失败，销毁隔离目标或停写生产目标，按**轮换前完整联合备份**恢复 PG、Redis 与 auth-secret，不单独回退密钥环。成功后重新生成恢复点和联合备份，才恢复写入口；旧备份按保留期与密钥托管策略继续保存，旧密钥环层必须随 PG 保留。旧原始 unit 可按密钥链映射到迁移后的伪名；丢失任一环层时必须明确失败，不能以新密钥替代旧备份。

## 失败诊断和演练记录

门禁拒绝启动时保持写入口关闭：

| 诊断 | 操作 |
| --- | --- |
| `snapshot dump tampered: HMAC mismatch` | 核对 escrow 的 `auth-secret` 与 Snapshot `.hmac`；从同一归档重取，不能删 `.hmac` 绕过。 |
| `manifest ... not found` / `incomplete snapshot` / revision 不一致 | gonacos 落后或缺不可变文档；恢复相同归档的完整 Snapshot，重新校验。 |
| `gonacos Snapshot mismatch` | Config/AI/Auth 任一内容与归档恢复点不一致；重取完整 Snapshot，不单独修补配置。 |
| `PostgreSQL HMAC key ring mismatch` | PG 不是该恢复点或密钥环缺失；重恢复整个 PG dump，不生成新密钥。 |
| `PostgreSQL/gonacos recovery point mismatch` | 某表内容、事件账本、token、schema 或 manifest 不同；核对归档哈希和目标库是否被写过，使用全新空库重新恢复。 |
| 迁移版本不同 | 停止；选与归档兼容的二进制/PG 客户端，在空库重试。 |

2026-10-06 隔离演练（PG16 Docker、内嵌 gonacos、签名加密 GPG 归档）：空数据集备份约 0.8 秒、恢复约 1.4 秒；含 workspace、环境、3 个 token 和已发布 flag 的数据集备份约 0.8 秒、恢复约 1.4 秒，`manifestRevision=1`、`flagRevision=1`、`controlVersion=18`、`tokenCount=3` 与恢复点一致。外部 Redis 路径另用 Redis 7 Docker 的真实 RDB + 独立 PG 库恢复并通过原生 `-verify-recovery-point`（约 3 秒，空业务数据）。完整 PostgreSQL 实验链路自动测试还把原始事件、去重账本、实验聚合与 gonacos Config 快照恢复到第二个数据库，校验 SDK 相同用户相同求值/实验 variant、token 可鉴权、重复事件只计 duplicate、报告 SRM/各组/决策一致；`go test ./test/e2e -run TestE2EPostgresExperimentLoop -count=1` 可重放（约 8 秒，真实 PG）。`go test ./internal/recovery ./internal/platform -run 'TestRecovery|TestPGReopen' -count=1` 重放门禁和只读打开检查。

注入结果：旧 gonacos Snapshot → manifest 不存在、拒绝；错误 `auth-secret` → Snapshot HMAC 不匹配、拒绝；PG token 内容变化但行数相同 → PG 内容摘要不匹配、拒绝；缺 HMAC 密钥环 → 密钥摘要不匹配、拒绝。四项进程退出码均为 1，均未打开 API。演练环境停写后无新增写入，观测数据丢失 0；生产 RPO 上界由最后一次成功归档与事故时间差实测并记录。每次定期演练记录归档 ID、源码 SHA、PG/gonacos 版本、数据量、停写时刻、备份完成时刻、恢复开始/校验通过/开放服务时刻、各注入退出码与日志摘要、最后事件时间和恢复后时间差、责任人及超出目标的处理工单。
